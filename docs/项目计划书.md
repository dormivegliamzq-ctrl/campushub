# CampusHub · 校园论坛社区 —— 项目计划书（简化版）

> 方向：Java 后端 | 身份：大三学生 | 周期：6 周（每周 8~10 小时）
> 定位：**简单、完整、有得聊**——全 CRUD 骨架，但每个模块都埋一个面试亮点

## 一、项目定位

一个校园论坛社区的纯后端 API 项目：注册登录 → 发帖 → 浏览 → 评论 → 点赞 → 关注 → 热门榜。

相比秒杀项目砍掉了 MQ、压测、JVM 调优、Docker 部署，**复杂度降一半，但保留了面试官爱听的三个点：缓存三大问题、Redis 排行榜、点赞防重**。

## 二、技术选型

| 技术 | 用途 | 说明 |
| --- | --- | --- |
| Spring Boot 3.5 + JDK 17 目标 | 主框架 | 复用已装环境（JDK23/IDEA） |
| MyBatis-Plus | ORM | 分页、软删除、代码生成 |
| MySQL 9.7（已装） | 数据存储 | 5 张表，索引设计是重点 |
| Redis 8.8（已装） | 帖子缓存 / 热门榜 / 点赞防重 | **只用到温和特性，不上锁和 Lua 高级操作** |
| JWT (jjwt) | 登录态 | 拦截器 + ThreadLocal 用户上下文 |
| Vue 3 + Element Plus + Vite | 前端（W6） | 配套社区页面，Node 已装，代码由 AI 全包 |
| Postman / Apifox | 接口测试 | W1~W5 阶段用 |

## 三、功能模块

1. **用户模块**：注册（BCrypt 加密）、登录（JWT）、个人信息查看/修改
2. **帖子模块**：发布、列表分页（最新/最热排序）、详情（浏览量+1）、编辑/删除（仅作者）
3. **评论模块**：对帖子评论、回复评论（两级）、删除
4. **点赞模块**：点赞/取消点赞、点赞数统计、**防重复点赞**
5. **关注模块**：关注/取关、关注列表、粉丝列表
6. **热门排行**：Redis zset 按热度加权排序，Top10 榜单

## 四、面试亮点设计（每个模块埋一个考点）

| 模块 | 具体做法 | 面试可讲点 |
| --- | --- | --- |
| 帖子详情缓存 | 两级缓存：帖子信息 + 帖子内容，热点帖设长过期 | 为什么热点内容适合缓存 |
| 缓存穿透 | 查询不存在的帖子时缓存空对象（短过期） | 空值缓存 vs 布隆过滤器 |
| 缓存雪崩 | 缓存过期时间加随机值（基础时间 ± 随机） | 为什么同时大批过期会打垮 DB |
| 热门排行榜 | zset 存帖子热度分 = 点赞×3 + 评论×2 + 浏览×1 | zset 跳表结构、为什么不用 MySQL ORDER BY 算排行 |
| 点赞防重 | Redis Set 记录已点赞 + DB 唯一索引 (post_id, user_id) 兜底 | 为什么缓存校验不能替代 DB 约束 |
| 计数一致 | 点赞/评论数更新与业务操作同一事务 | InnoDB 行锁、事务原子性 |
| 软删除 | deleted 字段 + MyBatis-Plus @TableLogic | 软删 vs 硬删，索引对软删查询的影响 |
| 分页 | MP 分页插件 + 时间线索引 | 深分页问题（LIMIT 100000,10 为什么慢） |
| 登录态 | JWT 拦截器 + ThreadLocal 取当前用户 | JWT 三段结构、无状态 vs Session |
| 操作日志（可选加分） | AOP 注解记录接口调用日志入库 | JDK 动态代理、AOP 失效场景 |

## 五、数据库设计

**user 用户表**：id, username(UNIQUE), password(BCrypt), nickname, avatar, bio, create_time

**post 帖子表**：id, user_id, title, content, view_count, like_count, comment_count, deleted, create_time, update_time
- `KEY idx_user_id (user_id)` 按用户查帖子
- `KEY idx_create_time (create_time)` 时间线分页

**comment 评论表**：id, post_id, user_id, parent_id(0=一级评论), reply_to_user_id, content, deleted, create_time
- `KEY idx_post_id (post_id)` 按帖子查评论

**post_like 点赞表**：id, post_id, user_id, create_time
- `UNIQUE KEY uk_post_user (post_id, user_id)` ★防重复点赞的数据库最后防线

**follow 关注表**：id, follower_id(粉丝), followee_id(被关注者), create_time
- `UNIQUE KEY uk_follower_followee (follower_id, followee_id)` 防重复关注
- `KEY idx_followee_id (followee_id)` 查粉丝列表

## 六、里程碑计划（6 周）

| 周 | 任务 | 交付物 |
| --- | --- | --- |
| W1 | 工程骨架 + 建表 SQL + 统一返回体/异常/日志 | 可运行空工程 |
| W2 | 用户模块：注册/登录 JWT/个人信息 + 拦截器 | 登录态闭环 |
| W3 | 帖子模块：发布/分页列表/详情/编辑删除 | 帖子 CRUD 闭环 |
| W4 | 评论 + 点赞（Redis Set 防重 + 唯一索引 + 事务计数） | 互动闭环 |
| W5 | 关注 + 热门榜 zset + 帖子缓存（防穿透/防雪崩） | 亮点全部落地 |
| W6 | **前端页面（Vue3 + Element Plus）** + AOP 操作日志（可选）+ README + 简历 bullet 定稿 | 可浏览的完整网站 + 简历素材包 |

### 前端（W6）说明

- 页面清单：登录/注册页、帖子列表页、帖子详情页（含评论区）、发帖页、个人主页（我的帖子/关注/粉丝）、热门榜页
- 全部页面代码由 AI 编写，遵循统一设计规范（配色/间距/排版）
- 你只需：`npm install`（国内镜像已配置）+ `npm run dev` 启动，浏览器访问
- 后端需开启 CORS 配置（W1 骨架里预留）

## 七、简历 bullet 示例（做完后润色）

- 基于 Spring Boot + MyBatis-Plus 开发校园社区后端，实现发帖、评论、点赞、关注、热门排行等模块
- 设计帖子详情缓存方案，通过空值缓存与随机过期时间分别解决缓存穿透与缓存雪崩问题
- 使用 Redis zset 维护帖子热度排行榜，点赞/评论/浏览加权实时更新
- 通过 DB 唯一索引 + Redis Set 双重校验实现点赞防重，保证计数准确

## 八、与秒杀项目的对比（为什么这个更合适现在）

| 维度 | 秒杀项目 | 本项目 |

| 周期 | 10 周 | 6 周 |
| 重环节 | MQ/压测/JVM 调优/Docker | 无 |
| 单点难度 | 高（并发正确性） | 低（CRUD + 温和缓存） |
| 面试亮点 | 深度高 | 广度够、好讲清 |
| 适合阶段 | 有经验后二刷 | **现在** ✅ |
